# USDT-TRC20 payment capability

`payment.usdt_trc20.v1` is a native `.s2plugin` capability with `platform=payment` and `account_type=none`. It cannot be mixed with OAuth transport or website widget capabilities. Its configuration UI and independently versioned verifier binary are shipped in the signed package. It receives no account-directory permission and never owns balance mutation or wallet signing keys.

The optional `TransportPlugin.VerifyPayment` RPC receives the host's immutable invoice identity, recipient, integer micro-USDT amount and transfer time window. A paid result contains the transaction hash, contract, sender, recipient, integer amount, block, timestamp and confirmation count. The host revalidates these fields and atomically claims the transaction hash in PostgreSQL before using its existing fulfillment pipeline. External generic payment notifications cannot confirm these orders.

The official contract is `TR7NHqjeKQxGTCi8q8ZY4pL8otSzgjLj6t` with six decimals. Authority: [Tether supported protocols](https://tether.to/en/supported-protocols/). Token symbols, names, logos and fiat value estimates are never payment evidence.

The verifier uses the fixed HTTPS host `apilist.tronscanapi.com`, with the API key only in `TRON-PRO-API-KEY`. Redirects are rejected. The discovery endpoint is [TRC20 transfers with status](https://docs.tronscan.org/en/api/transactions-and-transfers/trc20-transfers-with-status); every candidate also requires an independent [transaction-info](https://docs.tronscan.org/en/api/transactions-and-transfers/transaction-info) response. Successful contract execution, non-reversion, confirmed status, at least 20 confirmations and exactly one matching TRC20 transfer event are required. TRX, other contracts, ambiguous events and missing evidence fail closed.

Orders are priced in CNY using the site's existing limits, fees, bonuses and coupons. The fixed rate is **1 USDT = 6.5 CNY**. From host .7, the host computes `ceil(pay_cny / 6.5 * 100)` cents, adds a random integer from 0 through 9 cents, and tries successive one-cent amounts (at most 1,000 candidates). A database reservation keyed by wallet, contract and integer amount prevents concurrent orders from sharing an overlapping payment window. Amounts stay occupied through their original expiry even after cancellation or payment; only non-overlapping later windows may reuse them. The identifying adjustment is disclosed on checkout and does not increase the balance credit. Existing invoices retain their exact amounts, including legacy six-decimal amounts. Host .6 continues its original micro-unit allocation. Exhaustion returns an error asking for another order amount.

Transfers must occur within the original order window. Confirmation delays can be reconciled up to three hours after expiry. Cancellation is checked again at the atomic payment transition and is never reversed. Incorrect amounts and transfers outside the window require manual investigation. This plugin performs no automatic on-chain refund.

`sub2api_usdt_invoices` stores exact expected amounts, original prices, globally unique transaction hashes and proof. `sub2api_usdt_amount_reservations` stores the latest occupied interval end for each amount. Invoice history deliberately does not cascade on order or plugin deletion. Migration 389 removes the former permanent amount uniqueness constraint; binary rollback to .6 requires disabling the USDT plugin and its binding before restarting .6, while preserving all invoices and keys. Polling is throttled per order across processes; a bounded worker uses last-check times for fairness. Deactivation hides the method and prevents new chain verification. Previously verified claims can finish idempotent fulfillment.

Configuration uses the host's persistent encrypted plugin configuration. API keys are redacted from configuration responses; saving a blank key preserves the existing value. Wallet changes are blocked while orders remain recoverable. Back up the database and `DATA_DIR/secrets/plugin-config.key` together. Do not add keys to a manifest, source archive, public settings or screenshots.
