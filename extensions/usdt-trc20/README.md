# APIToken USDT · TRC20 支付插件

版本 1.2.0，需要宿主 2.23.0-apitoken.11 或后续兼容 2.x 版本。包含独立 Go 核验进程及独立后台配置 UI；通过现有 `/admin/plugins` 安装、配置、测试、启停、卸载。

填写 TRON 收款地址和 TronScan API Key，保存并测试连接，再启用插件。API Key 在服务器加密保存且不回显。插件不需要钱包私钥。支付方式会自动出现在充值页面。

汇率在插件配置页编辑，表示 **1 USDT = N CNY**（默认 6.5，支持 4 位小数）。手续费采用本插件的独立开关和费率（0–100%，支持 2 位小数）；关闭后为 0，不继承网站统一手续费。网站充值限额、赠送与余额规则继续生效。

新订单在服务端计算人民币应付金额与手续费，按本次配置的汇率换算为 USDT，向上保留两位小数，再随机增加 0.00–0.09 USDT。同一钱包有效期内金额冲突则逐次加 0.01 USDT。订单持久保存汇率、手续费、钱包、精确金额和有效期；修改配置只影响新订单。取消或已付的订单仍占用金额至原到期时间，过期后才可复用，识别尾数不增加余额。

充值页打开付款弹窗，独立付款链接使用相同界面。TRX、同名假币、错误金额和其他网络不自动到账；正确转账至少 20 次确认后进入原有充值账本。

从 1.0.2 升级：先备份并暂停支付插件，再升级宿主至 .9（自动执行追加的 390 号迁移），安装 1.1.0；填入原汇率 6.5 和需要的独立手续费，测试后重新启用。已有订单不重新计价。旧宿主不支持可变汇率，不能继续处理新增的可变汇率发票，因此 .9 起限制回退到 .9 或更新兼容版本。

从 1.1.0 升级：先备份，升级宿主到 .11，再安装签名的 1.2.0 插件并重新启用。配置及旧订单自动保留。1.2.0 支持保存新收款地址后继续按旧订单的原地址核验；新订单立即使用新地址。旧订单付款页提示地址变更并隐藏二维码，未付款者可以取消后重新下单；已付款者应保留订单等待核验，不要取消或重复付款。旧版核验插件仍保留更换钱包保护。

正常升级保留数据库与 `data/secrets/plugin-config.key`。后台单独显示已生效的新订单地址；编辑内容必须保存后才生效。测试只检查已保存配置；TronScan 401/403 会明确提示检查 API Key、接口权限和 IP 白名单。停用会暂停核验；如需卸载，先处理已付款订单。插件不自动退款。

构建：从 `backend/` 编译 `./cmd/usdt-trc20-plugin` 到本目录 `bin/linux-amd64/usdt-trc20`（Linux amd64）及 `bin/darwin-arm64/usdt-trc20`（本地验证）。使用 `build.py --output <path>.s2plugin --key <outside-repo-private.pem> --openssl <OpenSSL3>` 签名。`bin/` 为构建产物，不提交源码；私钥和 API Key 不打包。

完整协议、金额规则和官方接口来源见 [支付插件文档](../../backend/pkg/pluginapi/docs/usdt-payments.md)。

## 配置与执行边界

配置接口使用原有管理员认证、审计和二次验证策略；iframe 不持有管理员令牌。配置 UI 同时受 iframe sandbox 与响应头 CSP sandbox 限制（包括单独打开时），禁止同源存储访问、直接网络连接和表单提交。Bridge 校验具体窗口、随机会话、请求 ID；页面只使用 textContent/value 展示数据。

宿主和插件均校验收款地址、密钥格式、汇率和费率，拒绝重复键、未知字段、null、错误类型和越界数值。宿主禁止插件通过“规范化”改写管理员提交的支付配置。API Key 加密存储、不回显、不进入日志。TronScan 地址与 USDT 合约固定，禁止自定义回调/API 地址及重定向；插件不能调用账号目录或余额写入能力。

原生插件是受信任的可执行代码；签名、文件哈希和不继承宿主环境变量不等于操作系统沙箱，只安装已审查的可信签名插件。浏览器隔离行为参考 [MDN CSP sandbox](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/sandbox)。
